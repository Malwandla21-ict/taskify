# Taskify diagrams

All diagrams are SVG files. They open in any browser, and you can insert them into Word or PowerPoint with Insert → Pictures; they stay sharp at any size.

## State transition diagrams (UML state machines)

| File | What it shows |
|---|---|
| `state-task.svg` | One task: Posted → Accepted → In Progress → Awaiting Confirmation → Completed, plus Disputed, Cancelled and admin refunds. |
| `state-sale.svg` | A. One Taskify Protection sale order (Held, Disputed, Released, Refunded). B. The sale item it changes (Available, Reserved, Sold). |
| `state-rental.svg` | A. One rental booking: Requested → Awaiting Payment → Confirmed (Awaiting Collection → Out on Rent) → Return Check → Completed, plus Cancelled and damage outcomes. B. One extension request. |

State names are the values stored in the database (`tasks.status`, `sale_orders.status`, `sales_items.status`, `equipment_bookings.status`, `booking_extensions.status`). Labels read **event [guard] / effect**.

## Data flow diagrams (Gane & Sarson)

| File | What it shows |
|---|---|
| `dfd-level-0.svg` | Context diagram: the whole system as process 0, with every outside entity. |
| `dfd-level-1.svg` | Level 1: the ten processes, eight data stores (with the MySQL tables in each) and the outside entities. |

Both DFDs are generated by `build-dfd.js` from **one** list of flows, so the two levels always balance. The script also refuses to build if the model breaks a DFD rule: a flow that doesn't touch a process, a process with no input or no output, or a data store that's never written or never read.

To regenerate after changing the flows:

```
node docs/diagrams/build-dfd.js
```

## Entity-relationship diagram (crow's foot)

| File | What it shows |
|---|---|
| `erd.svg` | All 26 tables with every column, primary keys (PK), foreign keys (FK) and unique columns (UQ), and all 39 foreign-key relationships. |

It's drawn by `build-erd.js` from `erd-schema.json`, a structure-only snapshot of the live database (names, types and keys; no data). The legend also lists references the application keeps without a foreign key, such as `reports.context_type + context_id`. `blocked_content_attempts` and `flagged_uploads` have no lines on purpose: a blocked post is never saved (so there's nothing to link to), and a flagged image is matched by its URL when a listing is posted.

```
node docs/diagrams/build-erd.js
```

The diagrams describe the system as built on 11 October 2026. If a workflow changes, update the matching diagram (or `build-dfd.js`) in the same commit.
